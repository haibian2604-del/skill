# 全栈项目 → 简历项目经历

读一个真实存在的项目代码库，把「代码里的事实」翻译成「招聘方想看的项目经历」：
**项目名称 / 项目地址 / 开发时间 / 技术栈 / 核心模块（核心点）** 五要素齐全，
一次产出**均衡版、简洁版**两套文案。主要职责每条以**加粗模块名**开头，
用「针对……的问题，设计并实现……」把问题和方法绑死在一句里（格式细则见 writing-guide）。

## 核心原则

1. **不编造**。数字（用户量、QPS、性能提升）必须有出处：git、README、代码注释、用户口述。无出处一律用 `[待补充：xxx]` 占位符并集中列出，禁止虚构——简历上的每个数字面试都会被问到。
2. **写"我"不写"我们"**。单人项目天然成立；多人项目把成果落到个人动作上（git 作者分布是线索，拿不准就问用户角色分工）。
3. **每条职责 = 问题 × 方法 × 效果**。固定句式：「**模块名**：针对（具体问题），设计并实现（方法）；（机制展开），（效果）」。"使用了 WebSocket、Redis"（只有名词）和"实现了订单模块"（只有功能）都不合格。禁止「——【难点】」式标签，问题直接用"针对……"织进句子。
4. **不写码量指标**。代码行数、测试文件数不上简历；表数量、接口数、Agent 数量这类结构性数字可以。

## 工作流程

### Step 1 · 定位项目

项目路径按优先级取：用户明确指定的路径 > 当前会话工作目录 > 最近上下文里提到的仓库。确认目标是代码库本体（含 `package.json`/`requirements.txt`/`go.mod` 等任一），不是文档目录。

### Step 2 · 一键采集项目事实

```bash
python3 <本技能目录>/scripts/scan_project.py <项目路径>
```

脚本一次给出：**项目地址**（git remote）、**开发时间**（git 首末提交年.月）、技术栈（标记文件 + 依赖级框架识别）、中间件线索、目录结构、README 摘要、包管理文件关键字段。仅依赖 Python 标准库。

### Step 3 · 精读核心模块，提炼职责条目

脚本只能定位，不能理解。从目录结构挑 **4-6 个核心模块**，用 Read 精读路由/控制器/服务层/数据模型/核心页面，每个模块找到**配对的三端**：

- **问题端**：这个模块当初要对付什么坑——写到"什么场景下会坏"（长对话超出上下文窗口导致早期信息丢失、廉价模型输出截断且无视 schema、高并发超卖、工具硬编码扩展性差）
- **方法端**：设计/引入了什么机制——写到"怎么做"的颗粒度（三层记忆架构怎么分工、触发阈值是多少、什么锁兜什么场景、注册表模式怎么屏蔽差异），并给方法起名字（Think-Execute 循环、ChatClientRegistry 注册表模式）
- **效果端**：问题解决后带来什么——确保复杂指令连贯执行、让 LLM 仍能访问早期关键信息、新增工具无需改动核心代码

每条条目把三端连成一句话：「**模块名**：针对 X 问题，设计并实现 Y；Z 机制展开，W 效果」。找不到问题端的（照文档接的 SDK、脚手架自带的），降级为一句带过或放弃。全栈项目按「前端亮点 / 后端亮点 / 数据与部署亮点」三个侧面各找 1-2 个，避免只写一端。

### Step 4 · 补齐信息缺口

五要素里脚本拿不到的，**一次性列出追问**（表格形式：字段 / 为什么要 / 示例值，不超过 5 条），不要挤牙膏：

| 缺口 | 处理 |
|------|------|
| 项目地址（无 git remote） | 追问：GitHub/Gitee 链接或"暂不公开" |
| 开发时间（非 git 仓库） | 追问起止年月 |
| 个人角色（多人项目） | 追问分工，避免把他人工作写成自己的 |
| 量化数据 | 用户说不出就占位符，不强求 |

用户表示"先出稿"时，全部走占位符继续生成，文末集中列待补清单。

### Step 5 · 生成两版本文案

严格按 `references/writing-guide.md` 的规格与模板输出。两版差异速览：

| 版本 | 篇幅 | 适用场景 |
|------|------|----------|
| 均衡版 | 主要职责 4-6 条（完整句式） | **默认推荐**，标准校招/社招简历 |
| 简洁版 | 主要职责 2-3 条（压缩句式） | 简历空间紧张、多项目并列 |

两版共用同一个「项目信息」头部（名称/地址/时间/技术栈/核心模块），职责条目全部是「**模块名**：针对……设计并实现……」句式，差别只在条数与机制展开程度。动笔前先读 writing-guide。

### Step 6 · 落盘交付

写入 `<项目路径>/project-resume.md`（用户指定了其他位置则遵从），结构：

```markdown
# 项目经历 · <项目名>
> 生成自 <项目路径> · <日期>
## 项目信息（两版共用：名称/地址/时间/技术栈/核心模块）
## 均衡版
## 简洁版
## 待补充清单（如有占位符）
```

交付时告知用户：文件位置、推荐用均衡版、占位符需要本人补数。
