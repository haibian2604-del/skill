# 输出样例与 before / after 案例

## 标准样例（格式标杆，照此对齐）

```markdown
## 项目经验
### 智慧教育平台 \| 后端开发
2025\-10 \~ 2025\-12
项目地址：\[shturl\.cc/BJFjcqbkBpcxHGJCfhFgvhmOOZg9v\]\(shturl\.cc/BJFjcqbkBpcxHGJCfhFgvhmOOZg9v\)
**项目简介**：基于 Spring Cloud 微服务架构的职业技能培训平台，包含课程学习、优惠券、多渠道支付等功能，适配企业分布式高并发场景。
**技术栈**：Spring Boot、Spring Cloud、Nacos、MyBatis\-Plus、MySQL、Redis、RabbitMQ、XXL\-JOB
核心工作与成果：
1. 通用点赞模块设计：基于 Redis 重构点赞数据结构，解耦原有业务，封装通用组件，支持全平台业务复用，提升系统拓展性；
2. 签到功能性能优化：采用 Redis BitMap 存储签到记录，大幅降低存储占用，签到查询效率提升一个数量级；
3. 学习进度异步化：Redis 缓存结合 RabbitMQ 消息队列合并写入请求，异步持久化学习计划与进度，削峰填谷，保障高并发响应；
4. 积分排行榜方案：动态数据分表存储，搭配 XXL\-JOB 定时任务生成历史榜单，实现读写分离，减轻主库实时计算压力；
5. 高并发优惠券发放：使用 Redisson 分布式锁防止优惠券超发；自研 Base32\+JWT 兑换码生成算法，支持 20 亿唯一兑换码离线校验，无需频繁查询数据库。
```

值得抄的点：
- 每条「能力点命名：手段，结果」，分号结尾，无主语
- 技术栈里每个词都能在下面的条目里找到落点
- 结果有数字就给数字（20 亿唯一兑换码），没数字就给可验证的定性收益（提升一个数量级、无需频繁查询数据库）
- 项目简介写"是什么"，不写"我做了什么"

## 案例 1 · 后端：分布式任务调度平台

**原始材料（口述）**
> 一个定时任务调度平台，用 Go 写的，用了 etcd 做服务发现，MySQL 存任务，支持分片广播，我主要负责调度器和分片这块。原来单机跑，后来改成多节点。

**问题诊断**
- 没有量化结果
- "主要负责调度器和分片"边界模糊
- 未说明为什么需要改造

**追问清单**

| 字段 | 为什么需要 | 示例值 |
|------|-----------|--------|
| 我的角色与模块边界 | 区分个人/团队贡献 | 调度器 + 分片策略 owner，2/5 人 |
| 任务规模 | 体现系统量级 | 日调度 40 万次，峰值 300 TPS |
| 改造前后指标 | 唯一硬证据 | 调度延迟、可用性、故障恢复时间 |

**产出（补充数据后）**
```markdown
## 项目经验
### 分布式任务调度平台 \| 后端开发
2024\-03 \~ 2024\-09
**项目简介**：面向内部业务的分布式定时任务调度平台，支持分片广播、失败重试与故障自动漂移，承载日均 40 万次任务调度。
**技术栈**：Go、etcd、MySQL、Gin、gRPC、Prometheus
核心工作与成果：
1. 调度器多节点化改造：基于 etcd 租约选主重构调度器，通过版本号 + 租约续期实现故障 30s 内自动漂移，调度可用性由 99\.5% 提升至 99\.95%；
2. 高并发触发优化：设计时间轮 + 分片广播双层分发，将任务扫描复杂度由 O\(n\) 降至 O\(1\)，单机调度吞吐从 800 TPS 提升至 3200 TPS，P99 触发延迟由 3s 降至 200ms；
3. 重复调度治理：引入任务幂等表与执行器侧乐观锁双重校验，重复执行工单由月均 12 单降至 0；
4. 可观测性建设：接入 Prometheus 自定义指标与调度链路埋点，故障定位时长从小时级缩短至 5 分钟内。
```

## 案例 2 · 前端：数据看板（输入为架构图）

**架构图识别到的组件**：React + ECharts、WebWorker 计算层、SSE 推送、IndexedDB 缓存、CDN。

**可推断（标注待核对）**
- 大数据量下渲染卡顿 → 用 WebWorker 移出主线程
- 首屏慢 → IndexedDB 缓存上次数据 + 增量更新

**产出（示意，数字待用户核对）**
```markdown
## 项目经验
### 实时数据看板 \| 前端开发
**项目简介**：面向运营的实时数据看板，支持万级数据点的多维聚合与秒级刷新，覆盖 12 个业务线。
**技术栈**：React、TypeScript、ECharts、WebWorker、IndexedDB、SSE、Vite
核心工作与成果：
1. 大数据量渲染优化：将聚合计算下沉至 WebWorker，主线程渲染帧率由 12 FPS 提升至 55 FPS，交互卡顿投诉归零；
2. 首屏加载优化：设计「IndexedDB 缓存 + SSE 增量推送」加载策略，首屏可见时间由 4\.2s 降至 1\.1s，弱网下可先展示历史数据；
3. 图表组件沉淀：抽象 12 个通用图表组件并接入 Storybook，新看板接入周期从 3 天缩短至 0\.5 天。
```

## 案例 4 · 反例修正

**原始（典型错误）**
> 负责用户中心系统开发，使用 Spring Boot + Redis + MySQL + Kafka 技术栈，实现了用户注册、登录、信息查询等功能，优化了系统性能，提升了用户体验。

**问题**
- 无个人边界、无难点、无数字、技术词无因果、写成了功能清单

**修正后**
```markdown
## 项目经验
### 用户中心 \| 后端开发
**项目简介**：承载 2\.3 亿用户数据的统一账号中心，支撑 6 条业务线的注册、登录与鉴权，登录峰值 8000 QPS。
**技术栈**：Spring Boot、Spring Cloud、MySQL、Redis、Kafka、ShardingSphere
核心工作与成果：
1. 鉴权能力下沉：承接用户中心从单体拆分为独立服务，将登录鉴权链路封装为独立 SDK，被 6 个业务线复用，新增接入方接入成本由 5 人日降至 0\.5 人日；
2. 登录链路性能优化：针对峰值下的短信接口超时，引入本地令牌桶限流与验证码异步下发，接口 P99 由 2\.4s 降至 380ms，短信成本月降 3\.6 万元；
3. 数据平滑迁移：设计双写 \+ 对账补偿方案，完成 2\.3 亿用户数据从 MySQL 单库到分库分表集群的迁移，全程零停机、零数据不一致。
```
