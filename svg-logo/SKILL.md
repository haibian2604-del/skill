# SVG Logo 设计

为一个项目画 **手写几何 SVG** 的 logo：从名称与目的综合提炼设计简报，
用预设场景配色给 6 个差异化变体直接上色，收敛后精修、多尺寸验收。
全程零 API、零外部服务——所有图形都是手写 SVG。

**两条底线**（整个技能的地基）：

1. logo 是**几何构图**，不是插画。只用基本形状（圆、矩形、圆弧路径），
   一个 logo 只讲**一个**概念，最多 1–2 个核心元素。
2. **配色来自预设路线，不现场即兴**。每个场景的签名色/对比对/深底版都配好了
   （`references/color-palettes.md`），变体直接着色交付——黑白只作为单色回退版本，
   不是默认交付形态。

## 何时用

| 用户意图 | 做法 |
|---|---|
| "给这个项目 / 仓库画个 logo" | 走 §1 全流程 |
| "多出几个方案挑挑 / 帮我出 6 个" | 走 §1 第 2–6 步，停在被用户挑中之前 |
| "只想要个 favicon / 小图标" | 走 §1，但第 4 步只画 3 个变体，构图按小尺寸规则 |
| "就按第 N 个改" | 直接进第 7–8 步的定向迭代，**不要**整体重做 |
| "换个配色试试" | 读 `references/color-palettes.md`，换一条同场景或邻场景路线重着色，图形不动 |

## §1 标准流程

### 第 1 步：综合解读，写设计简报

有仓库就读 README / package.json / 官网，没有就用用户的一句话描述。
从五个维度提炼，产出一份 5 行以内的简报（不是一段话）：

- **名称**：字面含义、首字母、可读出的联想（"emotion-ball" → 球；"W." → wiki）
- **目的**：它解决什么问题？给谁用？（决定配色场景与气质）
- **领域**：知识库 / 部署工具 / 聊天机器人……（决定范式候选池）
- **受众**：开发者、大众消费者、企业……（决定直角还是圆角、密还是疏、冲击力档位）
- **具象物**：主题里最好画的一个东西（书、箭头、球……）

名字本身有画面感时优先画名字里的物；名字可做字母融合时把字母路线排进变体池。

### 第 2 步：选配色路线（先于画图）

读 `references/color-palettes.md`，按简报里的「目的 + 受众」定位场景，
场景内选 1 条主路线（展示页全部变体用它着色）+ 1 条备选路线（展示页提供
深底预览与换色说明）。受众越大众越偏向 memorable / high-impact；
已有品牌色时以品牌色为签名色派生路线。

### 第 3 步：范式匹配

读 `references/pattern-catalog.md`（画变体前必读），按「领域 + 具象物」挑
3–4 个范式家族作为候选池。举例：数据/AI → 点阵同心环、节点网络；内容平台 →
线系填充；名字可做字母 → 字母融合。

### 第 4 步：画 6 个彩色变体

统一 `viewBox="0 0 100 100"`，构图围绕 (50,50)，边缘留 10–15 单位。
先画形状骨架（此时可用 ink 单色勾），骨架成立后按主路线填色。
按 §2 多样性规则分配变体，**每个变体附一句设计理由**。
比例规范：线宽 2.5–4、间距 ≥8–12、留白 ≥40%、切口圆润。

### 第 5 步：展示页

把变体填进 `assets/showcase-template.html` 生成 `variants.html`（彩色卡片 +
深底预览条），交给用户打开挑选。

### 第 6 步：收敛

用户挑出 2–3 个方向后迭代：调比例/间距/旋转、合并两个变体的元素、增减密度，
或换一条配色路线重着色（图形不动）。**定向修改，不整体重做**。

### 第 7 步：定稿产出

写到项目根或用户指定目录：

- `<name>-logo.svg` —— 主版本（签名色着色）
- `<name>-logo-dark.svg` —— 深底版（**必须真的带 ink 底 rect**——透明底上换配色
  不是深底版，验收时也验不出来）
- `<name>-logo-mono.svg` —— 单色回退（`fill="currentColor"` 或 ink），README / 打印用
- `favicon.svg` —— 用场景里对比最强的一对色，单独做减法（去点缀、去细节）

### 第 8 步：验收（不能跳过）

```bash
python3 <skill>/scripts/render_check.py <name>-logo.svg        # 512/64/32/16 四档
python3 <skill>/scripts/render_check.py <name>-logo-dark.svg   # 深底版单独验
```

用 Read 工具查看 PNG，逐条过 §4 清单。

## §2 变体多样性规则（6 个变体怎么保证不重样）

**按范式家族分配**：纯几何、点阵、线系、点+几何混合、线+几何混合、节点网络各一；
主题合适时可替换为字母融合或分层构图。范式定义和 SVG 片段在
`references/pattern-catalog.md`，不要凭空发明第六种画法。

**在四个维度上刻意变化**：

| 维度 | 一端 | 另一端 |
|---|---|---|
| 密度 | 疏（3–4 个元素，大量留白） | 密（6–8 条以上的线系/点阵） |
| 对称 | 中心对称 | 刻意不对称张力（左下重右上轻） |
| 粗细 | 重（实心形状、粗线、深底容器） | 轻（细线、小点、透明度层次） |
| 复杂度 | 1–2 个元素 | 多元素但有序（网格/环状排布） |

**着色的变化**：6 个变体同用一条主路线，但允许两种容器策略交替——
约一半变体带"签名色大色块容器 + 借背景色的负空间图形"（应用图标形态），
一半为透明底的多彩图形（README / 印刷形态）。对比对给 favicon 留着。
同族检查：点阵出现在纯点阵和"点填充几何"里仍算同族，六变体中同一视觉母题
至多出现一次。

自查：把 6 个变体两两对比，若有两个"能靠改一个数字互换"，重画其中一个。

### 技术规范

- 变体阶段用路线里的实际 hex（可直接写死）；**定稿单色版**换成 `currentColor`。
- 相关元素用 `<g>` 分组；重复元素（点阵、多环）用 `<defs>` + `<use>` 复用。
- 线宽 2.5–4（主元素 3–4，次要 2）；点半径 2–8；元素间距 ≥ 8–12。
- 留白 ≥ 40% 画布；负空间切口必须是圆或圆角，不用尖角。
- 透明度只用于大面积背景层；前景小元素一律实心（半透明小元素 16px 下消失）。
- 网页展示可加微动画（20s 慢旋转 / 3s 呼吸脉冲），仅限展示页。

## §4 验收清单

1. **16px 可辨识**：缩到 16px 后还能认出概念吗？认不出 → 概念太复杂，砍元素。
2. **一个概念、单一焦点**：说得出"这是 X"吗？有没有两个等视觉重量的元素在竞争？
3. **撞型检查**：主形状有没有和更高频的日常物体共用轮廓，或与知名 logo/通用
   UI 语法撞型？已知高危：直杆+顶球 = 图钉；双等圆水平交叠 = Mastercard；
   轨道圆 + 进度弧 + 圆点旋钮 = loading 转圈。撞了 → 加差异化特征、换成
   刻度/透镜等独立主体、或换构图。
4. **配色成立**：签名色在浅底和深底上都够对比？是不是彩虹（>3 色）？
   high-impact 路线的签名色有没有以大色场出现？
5. **留白与密度**：画布留白 ≥ 40%？元素间距 ≥ 8–12？堆密了必然糊。
6. **对齐与张力**：落在网格上、光学居中；完全对称时有刻意的不平衡点。
7. **无边角裁切**：安全区检查（100 网格下内容不进边缘 10 单位）。
8. **单色回退可用**：mono 版去掉颜色后依然成立吗？不成立 → 形状层次不够。

## 常见坑（每一条都真的翻过车）

- **元素堆砌**：书 + 齿轮 + 闪电全画上。16px 下是一坨灰。→ 1–2 个核心元素。
- **直杆 + 顶球**：想画"生长的连线"，画出来是人人都认识的图钉/书签。
  隐喻要靠结构成立（分叉、多节点、渐次大小），不靠"我意图如此"。
- **6 个变体长得像**：同一想法换了线宽。→ 按范式家族分配，四维刻意变化。
- **黑白默认症**：变体全灰等用户"以后再上色"——用户要的是能直接用的彩色 logo。
  → 配色前置，预设路线直接着色。
- **彩虹配色 / 处处强调**：颜色超过 3 个或强调色到处都是。→ 签名色只有一处大色场。
- **蒙版裁切不留神**：clipPath 裁点阵会留月牙残点；只保留完整落在边界内的点。
  clip 出来的形状必须自己画边界描边，否则只剩悬空线段。
- **透明度当层级**：半透明小节点被读成灰色脏点，16px 下消失。前景用尺寸分层。
- **完美对称、完美居中**：没有张力。→ 留一个不对称的重心。
- **细描边**：2 以下的线宽在小尺寸下时有时无。→ 小尺寸场景用面不用线。
- **文字进 logo**：全名文字在图标尺寸不可读。→ 用字母融合或纯图形。
