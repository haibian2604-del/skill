# SVG Logo 设计

为一个项目画 **手写几何 SVG** 的 logo：先出 6 个真正不同的变体供挑选，
收敛后精修、上色、多尺寸验收。全程零 API、零外部服务——所有图形都是手写 SVG。

**两条底线**（整个技能的地基）：

1. logo 是**几何构图**，不是插画。只用基本形状（圆、矩形、圆弧路径），
   一个 logo 只讲**一个**概念，最多 1–2 个核心元素。
2. **探索阶段形状优先**：所有变体一律 `currentColor` 单色绘制，先定形，后上色。
   形不成立的颜色救不了它；先上色会被色彩掩盖结构缺陷。

## 何时用

| 用户意图 | 做法 |
|---|---|
| "给这个项目 / 仓库画个 logo" | 走 §1 全流程 |
| "多出几个方案挑挑 / 帮我出 6 个" | 走 §1 第 2–5 步，停在被用户挑中之前 |
| "只想要个 favicon / 小图标" | 走 §1，但第 3 步只画 3 个变体，构图按小尺寸规则 |
| "就按第 N 个改" | 直接进第 6–7 步的定向迭代，**不要**整体重做 |
| "logo 有点丑 / 改一下" | 读 §4 清单逐条排查，只动出问题的那一层 |

## §1 标准流程

### 第 1 步：提炼主题

有仓库就读材料，没有就用用户的一句话描述。要提炼的是三个词，不是一段话：

- **领域**：这个项目属于什么？（知识库 / 部署工具 / 聊天机器人……）
- **气质**：严肃工具、开发者玩具、还是面向大众？（决定后面直角还是圆角、密还是疏）
- **一个具象物**：主题里最好画的东西是什么？（wiki → 书/页，deploy → 箭头/云）

项目名字本身有画面感（如 "emotion-ball"）时，优先画名字里的物，其次才是领域抽象。

### 第 2 步：范式匹配

读 `references/pattern-catalog.md`（画变体前必读），根据主题气质挑 3–4 个范式家族
作为变体的候选池。对号入座举例：数据/AI → 点阵同心环、节点网络；开发者工具 →
点阵网格、几何+线条；内容/文本平台 → 线系填充；协作/工作流 → 胶囊点沿路径、
形状布尔交集。

### 第 3 步：画 6 个变体

统一 `viewBox="0 0 100 100"`，构图围绕 (50,50)，边缘留 10–15 单位内边距。
按 §2 的多样性规则分配变体，**每个变体附一句设计理由**（它抽象了主题的什么）。
变体之间必须"明显不同"，而不是同一想法的参数微调。

### 第 4 步：展示页

把变体填进 `assets/showcase-template.html` 生成 `variants.html`，交给用户打开挑选。
每个卡片 = 图形 + 变体名 + 一句设计理由。

### 第 5 步：收敛

用户挑出 2–3 个方向后进入迭代：可调比例/间距/旋转、合并两个变体的元素、
增减密度。**定向修改，不整体重做**——用户挑中的是那个结构，别弄丢它。

### 第 6 步：定稿上色与产出

给选中的方向上色（配色决策树见 `references/design-principles.md`），
写到项目根或用户指定目录：

- `<name>-logo.svg` —— 主版本（品牌色）
- `<name>-logo-mono.svg` —— 单色版（`fill="currentColor"`），README / 深色模式用
- `favicon.svg` —— 需要时单独做减法（去点缀、去细节），不要拿主版本缩放

### 第 7 步：验收（不能跳过）

```bash
python3 <skill>/scripts/render_check.py <name>-logo.svg   # 产出 512/64/32/16 四档 PNG
```

用 Read 工具查看产出的 PNG，逐条过 §4 清单。任何一条不过，回到对应步骤改。

## §2 变体多样性规则（6 个变体怎么保证不重样）

**按范式家族分配**：纯几何、点阵、线系、点+几何混合、线+几何混合、节点网络各一；
主题合适时可替换为字母融合或分层构图。范式定义和 SVG 片段在
`references/pattern-catalog.md`，不要凭空发明第六种画法。

**在四个维度上刻意变化**：

| 维度 | 一端 | 另一端 |
|---|---|---|
| 密度 | 疏（3–4 个元素，大量留白） | 密（6–8 条以上的线系/点阵） |
| 对称 | 中心对称 | 刻意不对称张力（左下重右上轻） |
| 粗细 | 重（实心形状、粗线） | 轻（细线、小点、高透明度层次） |
| 复杂度 | 1–2 个元素 | 多元素但有序（网格/环状排布） |

自查：把 6 个变体两两对比，若有两个"能靠改一个数字互换"，重画其中一个。
**家族不重复**：点阵出现在纯点阵和"点填充几何"里仍算同族——六变体中
同一视觉母题（点阵感、环状感）至多出现一次，否则收敛池会同质化。

### 探索阶段的技术规范

- 全部 `fill="currentColor"` / `stroke="currentColor"`，禁止硬编码颜色（此时还没上色）。
- 相关元素用 `<g>` 分组；重复元素（点阵、多环）用 `<defs>` + `<use>` 复用。
- 线宽 2.5–4（主元素 3–4，次要 2）；点半径 2–8；元素间距 ≥ 8–12。
- 留白 ≥ 40% 画布；负空间切口必须是圆或圆角，不用尖角。
- 透明度分层：背景层 0.1–0.4，次要元素 0.6–0.8，主元素 1.0。
- 网页展示可加微动画（20s 慢旋转 / 3s 呼吸脉冲），仅限展示页。

## §4 验收清单

1. **16px 可辨识**：缩到 16px 后还能认出概念吗？认不出 → 概念太复杂，砍元素。
2. **一个概念、单一焦点**：说得出"这是 X"吗？有没有两个等视觉重量的元素在竞争？
3. **撞型检查**：主形状有没有和更高频的日常物体共用轮廓（直杆+顶球 = 图钉，
   三角 = 播放键，圆+方孔 = 相机），或与知名 logo 混淆？撞了 → 加差异化特征
   （分叉、缺口、多节点）或换构图。
4. **留白与密度**：画布留白 ≥ 40%？元素间距 ≥ 8–12？堆密了必然糊。
5. **对齐与张力**：落在网格上、光学居中；完全对称时是否有刻意的不平衡点，
   还是"无聊的居中"。
6. **对比度**：形状之间、形状与背景之间有足够明度差吗？
7. **无边角裁切**：安全区检查（100 网格下内容不进边缘 10 单位）。
8. **单色版可用**：mono 版去掉颜色后依然成立吗？不成立 → 形状层次不够，补负空间。

## 常见坑（每一条都真的翻过车）

- **元素堆砌**：书 + 齿轮 + 闪电全画上。16px 下是一坨灰。→ 1–2 个核心元素。
- **直杆 + 顶球**：想画"生长的连线"，画出来是人人都认识的图钉/书签。
  隐喻要靠结构成立（分叉、多节点、渐次大小），不靠"我意图如此"。
- **6 个变体长得像**：同一想法换了线宽。→ 按范式家族分配，四维刻意变化。
- **先上色后定形**：渐变一糊，结构缺陷全被盖住。→ 探索阶段一律单色。
- **细描边**：2 以下的线宽在小尺寸下时有时无。→ 小尺寸场景用面不用线。
- **完美对称、完美居中**：没有张力，也撞满大街的"AI 生成感"。→ 留一个不对称的重心。
- **默认蓝紫渐变**：没有从主题出发的配色决定。→ 先找品牌色或气质色。
- **蒙版裁切不留神**：clipPath 裁点阵会在边缘留月牙残点，像渲染脏点；
  只保留完整落在边界内的点。clip 出来的形状必须自己画边界描边，否则只剩悬空线段。
- **透明度当层级**：半透明小节点被读成灰色脏点，16px 下直接消失。
  前景层级用尺寸区分，透明度只留给大面积背景层。
- **文字进 logo**：全名文字在图标尺寸不可读。→ 用字母融合（几何重构字母）或纯图形。
