# 分类体系 (Taxonomy)

> 本文件定义知识库中所有知识点的分类规则，是 schema 层的一部分（[[02-Rules/AGENTS.md]] 的配套文件）。
> 所有 LLM 创建/更新 wiki 页面时必须按本体系标注分类。
> 与用户共同演进：新领域出现时登记到 §3 词表，不要自创游离标签。

## 1. 分类原则

1. **两层各用各的维度**：
   - `01-Wiki/`：目录按**页面类型**（type）组织；主题用 frontmatter 字段 + 标签表达，**不建多层目录**。
   - `00-Raw/`：目录按**知识点**组织（见 §9）——原始资料无 frontmatter，只能靠文件夹分类。
2. **每页必有 domain**：主题领域是一级分类，必须且只能选一个，保证任何页面都能聚合浏览。
3. **标签宁少勿滥**：topic 标签 1-3 个为宜，从词表选，禁止同义标签（如 `AI` 与 `人工智能` 并存）。
4. **分类可迁移**：新知识同时可归入多个 topic，但 domain 取主要领域。

## 2. 分类维度

| 维度 | 字段 | 取值 | 必填 |
|------|------|------|------|
| 页面类型 | `type` | `summary` / `entity` / `concept` / `index` | ✅ |
| 主题领域 | `domain` | 见下方词表 | ✅ |
| 细分主题 | `tags` | 1-3 个，从词表选 | ✅ |
| 成熟度 | `status` | `seedling` / `growing` / `mature` | ✅ |

## 3. Domain 词表（一级主题）

| domain | 含义 | 典型内容 |
|--------|------|----------|
| `tech` | 技术/AI/编程 | LLM、算法、框架、工程实践 |
| `product` | 产品/设计 | 产品思维、交互设计、用户研究 |
| `business` | 商业/投资 | 公司、市场、商业模式、投资 |
| `academic` | 学术/研究 | 论文、理论、方法 |
| `life` | 生活/健康 | 健康、心理、习惯 |
| `reading` | 阅读/人文 | 书籍、人物、思想 |
| `other` | 其他 | 暂未归类的内容，lint 时重新归入 |

**扩展规则**：新领域出现 → 在本表登记一行 + 更新 `log.md`，禁止临时自创 domain。

## 4. Topic 标签规范（细分主题）

- 命名：小写英文连字符（`llm`、`transformer`、`frontend`），避免中文与英文混用
- 粒度：一个 tag 覆盖一个主题簇（cluster），不细分到单篇文章
- 登记：常用 tag 在 §6 索引中登记，便于查询与去重

## 5. 各页面类型的标签要求

| 类型 | domain | tags | 说明 |
|------|--------|------|------|
| summary | 源文件主要领域 | 源文件的主题词 | 继承源的领域 |
| entity | 实体所在领域 | 实体相关主题 | 实体多领域时取主领域 |
| concept | 概念所属领域 | 概念相关主题 | 与引用它的 summary 保持 domain 一致 |
| index | — | — | 索引页不参与分类 |

## 7. 按主题聚合浏览（Dataview）

`index.md` 中的动态区由以下查询生成（需安装 Dataview 插件）：

```dataview
TABLE domain AS 领域, type AS 类型, status AS 状态
FROM "01-Wiki"
WHERE type AND domain
SORT domain, type
```

按领域分组的替代写法（放入 index.md 各小节）：

```dataview
LIST FROM "01-Wiki"
WHERE type = "concept"
GROUP BY domain
```

### 8.3 约定

- 颜色是**辅助标识**，不替代分类字段本身；新增页面时颜色自动生效（按目录/标签匹配），无需手动标注
- 新增 domain / 新增常用 tag 时：同步在 `wiki-colors.css` 登记颜色，避免标签显示为默认灰色
- 禁止在同一目录中混放其他类型页面，否则图标颜色会误导

### 8.4 关系图谱配色（Graph View）

> 由 `.obsidian/graph.json` 的 `colorGroups` 实现。
> **双层着色策略**：子域标签组在前（细粒度、高对比）→ 路径兜底组在后（保证所有节点都有色）。
> 模板默认只带**路径兜底组**（见下表）；每登记一个新 tag，就在 `colorGroups` 数组**前部**追加一组标签规则。

**第一层 · 子域标签组（按主 `#tag` 着色，随内容增长逐步追加）**

| 子域 | query | 颜色示例 |
|------|-------|----------|
| _示例：某子域_ | `#<tag>` | 🔴 `#e03131` |

建组要求：子域色**跨色系分布**（红/靛/粉/橙/青/紫/绿/黄/棕），相邻簇明显可辨。

**第二层 · 路径兜底组（按目录着色，覆盖未匹配标签的节点）**

| 图谱分组 | query | 颜色 |
|----------|-------|------|
| 摘要 summaries | `path:01-Wiki/summaries` | 🟠 `#f08c00` |
| 实体 entities | `path:01-Wiki/entities` | 🔵 `#1971c2` |
| 概念 concepts | `path:01-Wiki/concepts` | 🟢 `#2f9e44` |
| 规则 02-Rules | `path:02-Rules` | 🟣 `#9c36b5` |
| 原始资料 00-Raw | `path:00-Raw` | ⚪ `#868e96` |

约定：

- **匹配顺序**：colorGroups 数组按顺序，节点取**第一个**匹配组。标签组在前 → 同主题不同类别（摘要/概念/实体）的节点会**同色聚合**成"主题簇"；路径组兜底保证无遗漏
- **关系类型限制**：⚠️ Obsidian 原生图谱**无法给"边/关系类型"单独染色**（边只能全局统一色）。"关系维度"改用：① 开启 `showTags` 看节点标签；② 用图谱搜索框按 `#tag` 筛选聚焦某子域；③ 文件树/列表视图用 CSS 按目录区分类别
- 新增常用 tag 时：在 graph.json 标签组区**追加一行**（含 rgb 数值）+ 同步 `wiki-colors.css`，保持两处一致
- graph.json 改后需**关闭并重开图谱视图**（或重启 Obsidian）才生效
- CSS 中的 tag 色用 hex；graph.json 用十进制 rgb（如 `#e03131` → `14692657`），换算：`R*65536 + G*256 + B`

## 9. 00-Raw 知识点目录规范（RAW 层分类）

> `00-Raw/` 的目录按**知识点（knowledge point）**组织，而非页面类型。
> 一个知识点 = 一个主题簇，与 §6 主题索引（tag 词表）对齐，但粒度更粗（多个 tag 可合并为一个夹）。
> 目的：源文件数量增长后仍能按主题快速定位，而不是全平铺在根目录。

### 9.1 知识点目录清单

| 文件夹 | 知识点 | 对应 tag | 文件数 |
|--------|--------|----------|--------|
| `00-Raw/inbox/` | 暂存区（未分类，等待 ingest） | — | 0 |

_首个知识点文件夹在首次 ingest 时创建并登记；每个新夹追加一行。_

### 9.2 归档规则

1. 新源先落 `inbox/`；ingest 时判定知识点
2. 匹配现有夹 → 移入；**不匹配 → 新建文件夹**（英文小写连字符，与 tag 词表同风格），并在 §9.1 表格**登记一行** + `log.md` 记一笔
3. 文件夹操作仅限**移动**，源文件**内容永不改动**
4. 一个夹内 ≥1 篇即可：宁可单文件独立成夹，也不为凑数硬塞错主题
5. 移动后**同步更新**所有 `[[00-Raw/<夹>/<文件名>]]` 链接（`sources:` 等），避免死链

### 9.3 判定知识点的优先级

1. 源标题 + 正文的**核心主题**（第一优先）
2. 与现有夹的**主题重叠度**（重叠高则归入，不新建）
3. 该源对应 wiki 摘要页的 `tags`（一一映射回文件夹）
4. 仍拿不准 → 归入最接近的夹，并在 `log.md` 标注「⚠️ 待复议」
