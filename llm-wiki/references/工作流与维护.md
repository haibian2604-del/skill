# 工作流与维护（操作手册）

> 本文件是 SKILL.md 的补充，仅在需要执行 Ingest / Query / Lint 或排查问题时读取。
> 落地在具体知识库时，以该库的 `02-Rules/AGENTS.md` 为准（它是 schema 层，优先级最高）。

## 0. 会话开场检查（每次进入一个知识库先做）

1. 读 `<vault>/02-Rules/AGENTS.md`（维护手册）与 `02-Rules/分类体系.md`（分类规则）
2. 读 `01-Wiki/index.md` 了解现有页面
3. `git -C <vault> log --oneline -3` 看上次会话做了什么
4. `grep "^## \[" 01-Wiki/log.md | tail -5` 看最近活动
5. `ls 00-Raw/inbox/` 看有没有待处理源

## 1. Ingest（摄入）

### 单篇

1. 读源文件全文（PDF 先转 markdown 或按页转图阅读；网页剪藏注意 frontmatter 是否被串号）
2. 与用户过一遍关键要点，确认强调重点（1-3 个问题即可，附选项）
3. 写摘要页 `01-Wiki/summaries/<源标题>.md`，模板见 `02-Rules/AGENTS.md` §2.5
4. 更新 `01-Wiki/index.md`：在「摘要」区加一行，格式 `- [[链接]] — 一句话摘要（YYYY-MM-DD，来源 ×1）`
5. **联动更新**：新建或更新涉及的实体页、概念页
   - 判断标准：摘要中出现、且值得独立成页的人/组织/产品/框架 → entity；理论/术语/方法 → concept
   - 已有页面：在「与既有知识的联系」「相关概念」中加回链，并把 `sources:` 数组追加新源、`updated:` 改为今天、`status` 视情况升级
   - 一篇源通常会触碰 5-15 个页面；命中已有概念页时**追加内容提要**，不要只加链接
6. `01-Wiki/log.md` 追加一条 `## [YYYY-MM-DD] ingest | 标题`
7. **归档源文件**：判定知识点 → 从 `inbox/` 移入 `00-Raw/<知识点>/`
   - 无匹配文件夹 → 新建（小写英文连字符），登记到 `02-Rules/分类体系.md` §9.1 + `00-Raw/README.md` + 根 `README.md`
   - 移动后**全局搜索该源路径**，更新所有 `sources:` 中的 `[[00-Raw/...]]` 链接（死链是高发错误）
   - 源文件名含 URL 残留或乱码时，归档时改为文档标题
8. `git add -A && git commit -m "ingest: <标题>"`（用户确认后推送）

### 批量

流程相同，跳过第 2 步；逐篇处理，每篇处理完立即更新 index，避免中途上下文丢失导致索引不一致。最后统一 commit。

## 2. Query（查询）

1. 先读 `01-Wiki/index.md` 定位候选页面 → 再读具体页面 → 需要时回溯 `00-Raw/` 原文
2. **答案必须引用来源**：链到对应摘要页或原始资料
3. 有复用价值的答案（对比表、分析、发现的联系）→ 问用户是否归档为新页面：
   - 归档为 concept/summary，并补齐 frontmatter 与回链
   - `log.md` 记 `## [YYYY-MM-DD] query | 问题简述`

## 3. Lint（健康检查）

逐项检查并产出修复清单：

| 检查项 | 做法 | 修复 |
|--------|------|------|
| 矛盾 | 对比同概念多页结论 | 标注 `⚠️ 已被 [[链接]] 更新/反驳` |
| 过期声明 | 查 `updated` 较旧的页 + 新源 | 更新内容，保留历史结论的标注 |
| 孤儿页 | 搜索谁引用了该页 | 补回链，或标 `status: seedling` 待并 |
| 缺失页 | 摘要中高频出现但无独立页的名词 | 建议新建 |
| 死链 | 检查 `[[00-Raw/...]]` 是否指向存在的文件 | 修正路径 |
| 数据缺口 | 哪些问题值得查证 | 登记到 `index.md` 待办区 |

- 修复清单需**先与用户确认**再执行
- `log.md` 记 `## [YYYY-MM-DD] lint | 发现 N 处，修复 M 处`
- 顺手校验 frontmatter：字段齐全、`domain`/`tags` 在词表内、`updated` 合理

## 4. 扩展规则

| 新增 | 登记位置 |
|------|----------|
| 新 domain | `02-Rules/分类体系.md` §3 词表 + `wiki-colors.css` 加色 + `log.md` |
| 新常用 tag | `分类体系.md` §6 词表 + `wiki-colors.css` 加色 + `graph.json` 加标签组 |
| 新知识点文件夹 | `分类体系.md` §9.1 + `00-Raw/README.md` + 根 `README.md` |
| 新页面 | `index.md` 对应区 + `log.md` |

配色换算：CSS 用 hex；`graph.json` 用十进制 rgb，`rgb = R*65536 + G*256 + B`。

## 5. 常见坑

- **搬家不改链**：源文件从 `inbox/` 归档后忘记更新 `sources:` → 死链。移动后必须全局 grep 旧路径
- **源文件被"顺便优化"**：`00-Raw/` 内容冻结，只允许移动。发现源里有错，在摘要页里标注，不回改源
- **摘要页堆成"读书笔记"**：摘要应服务于后续检索与交叉引用，重点是核心观点 + 与既有知识的联系，不是逐段复述
- **概念页只加链接不加内容**：命中已有概念时应补该源带来的新事实/新边界，否则 wiki 不会变厚
- **教程类源直接照抄**：旧版 API、错误示例要标注（如 `⚠️ 0.1.x 旧版 API`），不要静默继承
- **Dataview 未装**：`index.md` 顶部动态表格不渲染是正常现象，手工条目仍然有效

## 6. 协作与提交

- 知识库是普通 git 仓库；每次会话成果 ≈ 一次 commit
- commit message 前缀与 log 操作类型对齐：`ingest:` / `query:` / `lint:` / `update:` / `chore:`
- `.gitignore` 已排除 `.DS_Store`、`.obsidian/workspace.json`、`.workbuddy/`
