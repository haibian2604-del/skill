# Skill 用法查询

回答"某个 skill 怎么用"：**先定位文件，再读文件，最后按固定结构输出**。不凭印象回答——系统提示里的 skill 列表只有名称和一句话描述，用法细节只在 SKILL.md 里。

## 工作流

1. **定位**（一条命令，别手工翻目录）：

```bash
/Users/kk/.workbuddy/binaries/python/envs/default/bin/python \
  <skill_dir>/scripts/find_skill.py --name <技能名或关键词>
```

- 不知道确切名字 / 用户想浏览：`--list`（全量，按来源分组，`*` 标记 agent_created）
- 查搜索范围本身：`--roots`
- 命中多个同名（项目级 vs 用户级 vs 插件内置）：脚本会标出被遮蔽的那个，两个都要读一下差异

2. **读 SKILL.md**（渐进式，别一次全读）：
   - 先读 frontmatter + 正文标题（`head -60`）
   - 需要细节再读 `references/`（脚本会报有哪些文件、各几个）
   - 脚本类 skill：看 `--help` 或脚本头部 docstring 的用法行，不要通读源码
   - 输出目录路径不要用 `~`，给绝对路径

3. **可选实测**（只读验证，别执行真动作）：跑 `--help`、`--list`、`--roots` 这类无副作用命令确认参数真实存在。不要为了"验证用法"去跑会改文件的命令。

4. **按模板输出**。用户问的是"用法"，所以输出面向"怎么用"，不是复述文档。

## 输出模板

按此顺序、按需裁剪（没有的项写"SKILL.md 未说明"，**不要编**）：

| 项 | 内容 |
|----|------|
| 一句话作用 | 它解决什么问题 |
| 何时触发 | 自然语言触发词 / 场景；有 `/name` 斜杠形式就写出来 |
| 怎么用 | 直接对 Agent 说的话（给 2-3 个可用句式示例） |
| 需要提供什么 | 输入材料、前置条件（路径、文件、账号、授权） |
| 执行流程 | 3-6 条步骤摘要，让用户知道会发生什么 |
| 产出物 | 交付什么、落在哪（文件类型/位置） |
| 依赖与环境 | 脚本、运行时、外部工具/插件、需装的包 |
| 注意与坑 | 限制、边界、易踩的坑、会写文件/需确认的地方 |
| 位置 | SKILL.md 绝对路径；同名遮蔽情况 |

- 中文技能：原文已有的术语保留，别翻译成英文
- 长文档别整段抄，压成要点；用户要细节再展开某一项

## 边界

- **只解释，不执行**。本技能不代跑目标 skill 的工作；用户说要"用一下"，就直接切过去用那个技能
- **不臆造能力**。SKILL.md 里没写的功能，明确说"未说明"，不要按名字猜
- **找不到本地 skill** → 先 `--list` 模糊看；仍没有，建议走推荐市场搜索（`workbuddy_marketplace_skill` action=search），并说明是本机未安装而非不存在
- **问"有没有能做 X 的技能"** → 属于 find-skills 的职责，本技能只在用户已经知道技能名/想浏览列表时介入

## 环境

- 脚本：`scripts/find_skill.py`，仅用 Python 标准库
- 搜索根按优先级：项目级 `<cwd>/.workbuddy/skills/` → 用户级 `~/.workbuddy/skills/` → 插件/市场缓存 `~/.workbuddy/plugins/cache/<源>/<插件>/<版本>/skills/`（同名多版本取最新）→ 应用内置 → `~/.claude/skills/`、`~/.codex/skills/`
- 市场缓存里 `__skillhub` 后缀（如 `drawio__skillhub`）表示来自推荐市场安装
